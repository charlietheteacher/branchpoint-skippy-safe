# Future HTML Game Direction

This repository is not yet an HTML implementation project.

The current purpose is to preserve the approved SKIPPY SAFE story and design so a later HTML build begins with the simulation's instructional identity intact.

## Future development question

The key question is:

> What is the best HTML expression of SKIPPY SAFE?

Not:

> How do we copy the Gemini Gem into a webpage?

A future browser version should use HTML only where it improves the experience.

Potential strengths worth exploring later include:

- visual laboratory exploration
- clickable equipment and areas
- evidence discovery
- changing environmental states
- persistent Skippy damage
- visible equipment condition
- labels and SDS excerpts
- different routes through the laboratory
- replay variation
- consequences that affect later situations
- short reasoning interactions at important decision points
- local save/resume without student accounts

## Preserve from the current simulation

Future work should preserve:

- the student as Laboratory Safety Lead
- Skippy's character
- Skippy's competence
- Skippy's risk-estimation blind spot
- evidence before conclusion
- open investigation
- safe, unsafe, and ambiguous conditions
- realistic laboratory consequences
- persistent state
- student responsibility for central decisions
- final laboratory-readiness judgment
- Creation Mandate stewardship reflection where appropriate

## Avoid

Do not automatically turn the simulation into:

- a normal multiple-choice quiz
- a sequence of safety violations to click
- a linear slideshow
- an arcade game with safety vocabulary attached
- a fake chatbot
- a game where Skippy is always wrong
- a checklist where every suspicious object is dangerous

## Current instruction

Do not build the HTML game yet.

When development resumes, begin by rereading `SKIPPY_SAFE_STORY_AND_CONCEPT.md` and the then-current approved Skippy Safe source materials before choosing a technical architecture.
